              Solicitar token
              
Configure a rota e os nomes dos campos conforme a API. Essas preferências ficam salvas localmente; valores de credencial são pedidos a cada envio e nunca entram no histórico.

              
              
              

                

                

              

              

                

                

              

              
              
              
HTTP não cifra credenciais. Confirme o destino antes de solicitar token.

              
              
Depois, use {{token}} em Params, body ou URL base. Novos tokens usam proteção local; migre registros antigos em Configurações.

              
            

            

              OAuth 2.0 · Client Credentials
              
Use para integração serviço a serviço. O segredo é pedido a cada envio e nunca entra no perfil, no histórico ou na URL.

              

                

                

                

                
Separe scopes por espaço. O campo é opcional.

                

              

              
              
HTTP remoto expõe client_secret e token na rede. Prefira HTTPS; HTTP local é permitido.

              
              
Perfil (URL, client ID e scopes) é salvo por ambiente. Client secret fica só na memória. O token salvo usa proteção local.

              
Nenhum token OAuth salvo neste ambiente.

              
            

            

              OAuth 2.0 · Authorization Code + PKCE
              
Use quando a API acessa dados em nome de um usuário. O Vortix abre o provedor em outra aba, usa PKCE S256 e recebe o retorno por loopback. Este fluxo público não pede client_secret.

              

                

                

                

                

              

              

                
                

                  
                  
                

              

              
Cadastre a URI exata mostrada. O Vortix só recebe callback em 127.0.0.1; HTTP remoto é bloqueado. O provedor precisa aceitar Authorization Code com PKCE S256.

              
              
              
Os tokens ficam só em memória até você marcar cada opção. Valores salvos usam proteção local; renovação automática ainda não está disponível.

              
Informe a URL de autorização para calcular a redirect URI exata.

              
              
            

          

          

            

              
Resposta → variável
Guarda um valor da resposta no ambiente ativo.

              
            

            
            

              

              

              

            

            
            
A variável fica no ambiente ativo e pode ser usada como {{token}}. Valores sensíveis novos usam proteção local; a resposta completa não é salva.

            

              Como isso funciona no Insomnia
              
Depois de receber a resposta, o Insomnia usa insomnia.response.json() e insomnia.environment.set(). O código equivalente abaixo pode ser copiado para Scripts → After-response.

              
const body = insomnia.response.json();
insomnia.environment.set("token", body.access_token);

              
              
Exemplos de caminho: access_token, data.token ou result.jwt. Para uma resposta sem JSON, escolha “Texto inteiro”.
