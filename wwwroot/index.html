              Solicitar token
              
Configure a rota e os nomes dos campos conforme a API. Essas preferências ficam salvas no workspace; valores de credencial são pedidos a cada envio e nunca entram no histórico.

              
              
              

                

                

              

              

                

                

              

              
              
              
HTTP não cifra credenciais. Confirme o destino antes de solicitar token.

              
              
Depois, use {{token}} em Params, body ou URL base. No modo local, tokens salvos usam proteção no SQLite; no modo público, ficam no IndexedDB sem criptografia automática.

              
            

            

              OAuth 2.0 · Client Credentials
              
Use para integração serviço a serviço. O segredo é pedido a cada envio e nunca entra no perfil, no histórico ou na URL.

              

                

                

                

                
Separe scopes por espaço. O campo é opcional.

                

              

              
              
HTTP remoto expõe client_secret e token na rede. Prefira HTTPS; HTTP local é permitido.

              
              
Perfil (URL, client ID e scopes) é salvo por ambiente. Client secret fica só na memória. No modo público, tokens salvos ficam no IndexedDB sem criptografia automática.

              
Nenhum token OAuth salvo neste ambiente.

              
            

            

              OAuth 2.0 · Authorization Code + PKCE
              
Use quando a API acessa dados em nome de um usuário. O Vortix abre o provedor em outra aba, usa PKCE S256 e recebe o retorno pela URI configurada. Este fluxo não pede client_secret.

              

                

                

                

                

              

              

                
                

                  
                  
                

              

              
Cadastre a URI exata mostrada. O provedor precisa aceitar Authorization Code com PKCE S256. Fluxos remotos exigem HTTPS.

              
              
              
Os tokens ficam só em memória até você marcar cada opção. No modo público, valores salvos ficam no IndexedDB sem criptografia automática; renovação automática ainda não está disponível.

              
Informe a URL de autorização para calcular a redirect URI exata.

              
              
            

          

          

            

              

                
Antes da request
Crie valores temporários para usar como {{request_id}}. Eles só existem nesta chamada.

                
              

              
              
              
No modo público, textos autorizados ficam no IndexedDB sem criptografia automática. Para segredos, use referências ao cofre.

              

              
Nenhuma ação pré-request. Adicione UUID, timestamp UTC ou um valor com templates.

              
Ações rodam em ordem. UUID e timestamp UTC são gerados por envio; templates podem usar variáveis anteriores. Prioridade: dados do Runner > ação pré-request > cofre > ambiente. Sem consentimento, textos literais são omitidos ao salvar; guarde segredos no ambiente/cofre.

              

                Dica: usar um ID no caminho e em um header
                
Adicione um UUID chamado request_id. Depois, use {{request_id}} nos campos da request. Para compor outro valor, escolha Template e use as variáveis da ação anterior ou do ambiente.

                
Rota: /orders/{{request_id}}
Header: X-Request-Label: {{request_label}}

UUID → request_id
Template → request_label = {{tenant}}-{{request_id}}

              

            

            

              
Depois da resposta → variável
Guarda um valor da resposta no ambiente ativo ou cofre.

              
            

            
            

              

              

              

              

            

            
            
O destino padrão é o ambiente ativo. Escolha Cofre cifrado para gravar no cofre desbloqueado; se o cofre estiver bloqueado ou o armazenamento falhar, a captura falha e não copia o valor para o ambiente. No modo local, valores sensíveis usam proteção no SQLite; no modo público, o IndexedDB não é criptografado automaticamente. A resposta completa não é salva.

            

              Como isso funciona no Insomnia
              
Depois de receber a resposta, o Insomnia usa insomnia.response.json() e insomnia.environment.set(). O código equivalente abaixo pode ser copiado para Scripts → After-response.

              
const body = insomnia.response.json();
insomnia.environment.set("token", body.access_token);

              
              
Exemplos de caminho: access_token, data.token ou result.jwt. Para uma resposta sem JSON, escolha “Texto inteiro”.

              Como funciona o contrato OpenAPI?
              
    Ao importar uma especificação, você pode validar o body da request antes de enviar. O Vortix também verifica status, Content-Type e estrutura JSON da resposta no envio manual ou no Runner. Falhas são avisos e não impedem o envio; “Parcial” indica regra não suportada ou contrato incompleto.
    
              
    Referências locais limitadas são lidas do próprio arquivo. Referências externas não são carregadas. Exemplos e valores do body não entram no contrato.
    
            
    
            
    
            
    
            
    
              Compatibilidade com Insomnia e Postman
              
    As regras são convertidas em scripts After-response do Insomnia e Post-response do Postman ao exportar nesses formatos. Scripts são código executável; revise antes de usar.

      Histórico de respostas
      
        
      
          
          
        
      
        
      Bodies de resposta ficam desativados por padrão. No modo local, são protegidos no SQLite; no modo público, ficam no IndexedDB sem criptografia automática. Desativar não apaga bodies já salvos; limpe o histórico para removê-los. Bodies de token nunca são guardados.
      
      
      
      
      
        
      Ambientes
      Separe variáveis de desenvolvimento, homologação e produção.
      
        
      
      
      
      
        
      Cofre de segredos
      Opcional e por ambiente. Os valores são cifrados no navegador com WebCrypto PBKDF2-SHA-256 e AES-GCM-256 usando dbRead/dbWrite('settings', …); a senha e a chave não são salvas nem enviadas ao servidor.
      
        
      
        
      
          
          
          
      A senha não é armazenada e não pode ser recuperada. Ao recarregar ou bloquear, os valores descriptografados saem da memória.
      
          
      
            
            
            
          
      
        
      
        
      
          
      
            
      
            
      
            
          
      
          
      Nomes no cofre (valores nunca são exibidos)
      
          
        
          
        Use {{nome}} em URL base, rota, Params, Headers, Auth, Body, GraphQL e multipart. A precedência é dados do Runner > cofre > ambiente.
        
        
        
      
        
      
        
        
        Backup do workspace
        Inclui histórico, coleções, pastas, ambientes e configurações. Você pode baixar JSON simples ou protegido por senha.
        
        
        
          
          
          
          
        
        
      
        
      
        
        
        Proteção dos dados
        Novos tokens, Headers, Params sensíveis e Bodies usam ASP.NET Core Data Protection. Registros antigos migram após backup; cópias legadas do navegador não são apagadas.
